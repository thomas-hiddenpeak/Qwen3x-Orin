# Qwen3.6-27B-NVFP4 per-block 零值统计

## 结论

- checkpoint：`nvidia/Qwen3.6-27B-NVFP4@0893e1606ff3d5f97a441f405d5fc541a6bdf404`
- NVFP4 范围：64 层 × `gate/up/down`，加 `lm_head`，共 193 个张量。
- 逻辑 NVFP4 权重：18,384,158,720 个；严格零值：1,461,170,821 个，零值率 **7.9479885006%**。
- size-16 quant block：1,149,009,920 个；其中 829,302,967 个至少含一个零，占 **72.1754401389%**。
- **全零 block 为 0**。因此，按 size-16 block 做整块跳过没有可利用空间；若用于 kernel 稀疏优化，应继续检查 2:4 或更细粒度的零位置模式。

## 统计口径

一个 quant block 是同一输出 row 沿 K 连续的 16 个逻辑权重，即 8 个 packed bytes 和一个 E4M3 block scale。

E2M1 的 `0x0`（`+0`）与 `0x8`（`-0`）都计作数值零：

- `+0`：730,618,492
- `-0`：730,552,329

全部 1,149,009,920 个 block scale 与 193 个 tensor scale 都是有限正数，所以本 checkpoint 中“严格反量化后等于 0”与 E2M1 `0x0/0x8` 完全等价，没有 scale 诱发零或 FP32 下溢。

不能用 `packed_byte == 0` 代替 nibble 统计：这种写法会漏掉单侧零和全部 `0x8` 负零编码。

- 最高：`layer_63`，零值率 8.15664703%。
- 最低：`layer_03`，零值率 7.84228605%。
- 64 层的完整明细在 `summary.csv`，每层汇总 `gate/up/down` 三个 NVFP4 张量。

## 验证

- `qwen3x-inspect checkpoint --require-shards`：3/3 shards、2,194/2,194 tensors 的 index/header contract 全部通过。
- 两次全量 memmap 扫描结果一致。
- 与独立逐 nibble 全模型扫描逐项一致。
- block 直方图之和、按桶加权零值数、E2M1 code 直方图、block scale 数和逻辑 shape 全部闭合。

默认未输出 1,149,009,920 行逐块明细；即使每块只保存一个 `uint8` zero-count，也约为 1.15 GB。现有输出保留了 overall、projection、layer 和 tensor 四个粒度的精确直方图。
